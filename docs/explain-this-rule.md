# กฎ "Explain This" และการ Verify on map

## กฎ

ก่อนรันโค้ดที่ AI เขียนทุกบล็อก ต้องเขียน **คำอธิบายภาษาไทยของคุณเอง** ใน Markdown cell หรือ comment อย่างน้อย 3 ข้อ:

1. **บล็อกนี้ทำอะไร** (ภาษาธรรมดา ไม่ใช่แค่แปลชื่อฟังก์ชัน)
2. **ข้อมูลเชิงพื้นที่เปลี่ยนไปอย่างไร** (CRS / resolution / extent / shape)
3. **จุดที่อาจผิดเชิงพื้นที่** อย่างน้อย 1 จุด และจะตรวจอย่างไร

> คะแนนแล็บมาจากขั้น Review (Explain This) เป็นหลัก ไม่ใช่จากการที่โค้ดรันผ่าน
> คำอธิบายที่คัดลอกจาก AI โดยไม่ปรับเป็นภาษาของตนเอง ถือว่าไม่ผ่านขั้น Review

## เทมเพลต

```markdown
### Explain This — <ชื่อบล็อก>
- **ทำอะไร:** ...
- **ข้อมูลเชิงพื้นที่เปลี่ยนอย่างไร:** (CRS: ... | ความละเอียด: ... | shape: ...)
- **จุดเสี่ยง + วิธีตรวจ:** ...
```

## ตัวอย่างระดับดี vs ระดับพอใช้

| ระดับ | ตัวอย่าง |
|---|---|
| ต้องปรับปรุง | "บล็อกนี้โหลดภาพมาแสดง" |
| พอใช้ | "ดึงภาพ Sentinel-2 จาก STAC แล้วตัดเฉพาะพื้นที่ที่สนใจมาแสดงสีจริง" |
| ดี | "ดึง asset `visual` (RGB 8-bit, 10 m) ของภาพที่เมฆน้อยสุด ตัดด้วย window ตาม bbox ที่แปลงเป็น CRS ของภาพแล้ว shape ควรเป็น (3, ~224, ~224) จุดเสี่ยง: ถ้าลืมแปลง bbox จาก EPSG:4326 เป็น UTM ภาพจะว่างหรือผิดตำแหน่ง ตรวจโดยดูว่า min/max ไม่ใช่ศูนย์ทั้งหมดและเทียบตำแหน่งกับ Google Maps" |
